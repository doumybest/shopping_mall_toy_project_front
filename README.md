# ソソマーケット フロントエンド

## 1. プロジェクト概要

ソソマーケットは、日本語と日本円（JPY）を使った学習用ショッピングサイトです。フロントエンドは Vue 3 と TypeScript で、商品検索、メール認証付きの会員登録、イベントバナー、カート、クーポン、模擬決済、配送状況付きの注文履歴、ポイント、レビュー、管理画面を提供します。商品や会員のデータはバックエンドの API から取得します。

### 使用技術

| 区分 | 技術・役割 |
| --- | --- |
| UI | Vue 3、Composition API、単一ファイルコンポーネント |
| 型定義 | TypeScript、vue-tsc |
| ページ遷移 | Vue Router、HTML5 History モード |
| 開発・ビルド | Vite、pnpm |
| ブラウザーテスト | Playwright |

## 2. 環境設定

### 2.1 必要なソフトウェア

| ソフトウェア | 条件・用途 |
| --- | --- |
| Node.js | `^20.19.0` または `>=22.12.0`。フロントエンドの開発・ビルドに使用 |
| pnpm | `11.25.0`。`package.json` の `packageManager` で指定 |
| エディター | フロントエンドの編集には VS Code などを使用可能 |

バージョンと PATH の設定を確認します。

```powershell
node --version
npm.cmd --version
```

pnpm が未インストールの場合は、次を実行してターミナルを開き直します。

```powershell
npm.cmd install --global pnpm@11.25.0
pnpm.cmd --version
```

PowerShell の実行ポリシーで `pnpm.ps1` が拒否される場合は、この README のように `pnpm.cmd` を使用してください。macOS・Linux などでは `pnpm` に読み替えます。

### 2.2 フロントエンドの依存関係

`front` フォルダーで実行します。

```powershell
pnpm.cmd install
```

VS Code では **Vue - Official** 拡張機能を使用すると、`.vue` 内の TypeScript の補完や型エラーを確認できます。依存パッケージのバージョンは `package.json`、解決済みの構成は `pnpm-lock.yaml` で管理します。

## 3. 起動方法とコマンド

### 3.1 開発サーバーを起動

バックエンドを起動し、[稼働確認 API](http://localhost:8080/api/health) が応答することを確認します。会員登録を試す場合は、バックエンドで SMTP の設定も行います。 [バックエンドの起動と環境設定](../back/README.md)

別のターミナルで `front` フォルダーに移動し、次を実行します。

```powershell
pnpm.cmd dev
```

ブラウザーで [開発画面](http://localhost:5173) を開きます。Vite は `/api` を既定で `http://localhost:8080` に転送します。開発サーバーを停止するには Ctrl+C を押します。

### 3.2 フロントエンドのコマンド一覧

以下はすべて `front` フォルダーで実行します。

| コマンド | 内容 |
| --- | --- |
| `pnpm.cmd install` | 依存パッケージをインストール |
| `pnpm.cmd dev` | 開発サーバーを起動。ポートは `5173` 固定で、使用中ならエラー |
| `pnpm.cmd type-check` | `.ts` と `.vue` を `vue-tsc --noEmit` で型チェック |
| `pnpm.cmd build` | 型チェックに成功した後、`dist/` に配布用ファイルを生成 |
| `pnpm.cmd preview` | ビルド済みファイルをローカルで確認。API の接続先は別途設定が必要 |
| `pnpm.cmd test:e2e` | Playwright によるブラウザーテストを実行 |

バックエンドのポートを変更した場合は、フロント起動前にプロキシの接続先を指定します。

```powershell
$env:API_PROXY_TARGET = 'http://localhost:8081'
pnpm.cmd dev
```

`API_PROXY_TARGET` は Vite 開発サーバー用の設定です。変更後は Vite を再起動してください。配布先の Web サーバーでは、別途 `/api` の転送を設定します。

### 3.3 E2E テスト

E2E 用にバックエンドの JAR をビルドします。次に `front` フォルダーで JDK 21 の場所を設定し、Playwright を実行します。 [バックエンドのビルド手順](../back/README.md)

```powershell

# パスは自分の JDK 21 のインストール先に置き換えます。
$env:JAVA_HOME = 'C:\path\to\jdk-21'
pnpm.cmd test:e2e
```

既定のブラウザーはインストール済みの Microsoft Edge です。Edge を使用しない場合は次のように Chromium を準備します。

```powershell
pnpm.cmd exec playwright install chromium
$env:E2E_BROWSER = 'chromium'
pnpm.cmd test:e2e
```

JAR の保存場所を変えた場合は `E2E_BACKEND_JAR` にそのファイルパスを指定できます。既定値は `../back/target/shopping-mall-0.1.0-SNAPSHOT.jar` です。

テストではフロント `5174`、API `18080`、ローカル SMTP `11025`、テスト用メールボックス `18081` を使用します。これらのポートを空けておいてください。専用 H2 メモリー DB を使用し、Oracle や通常の `demo` ファイル DB は使いません。テストメールはローカルで受信し、外部には送信しません。

認証・購入・ポイント・キャンセル、管理者の商品 CRUD、未ログイン時のバナー閲覧とログインへの誘導、クーポン決済、配送状況の反映、URL の直接入力・アクセス制御・履歴移動などを検証します。テスト終了時に起動したサーバーとブラウザーを終了し、スクリーンショットや失敗時の trace は `.test-results/` に保存します。

### 3.4 配布・運用時の設定

`pnpm.cmd build` で生成した `dist/` を Web サーバーから配信します。`/api` は同一オリジンでバックエンドへ転送してください。

Vue Router は `createWebHistory` を使用しています。`/orders` などの画面 URL を直接開いたり再読み込みしたりできるよう、フロントの画面 URL は `index.html` にフォールバックさせます。`/api` はこの対象にせずバックエンドへ転送します。Vite 開発サーバーは画面 URL のフォールバックを処理しますが、配布先では別途設定が必要です。

HTTPS で運用する場合は、バックエンドの `COOKIE_SECURE=true` も設定します。

## 4. プロジェクト構成

```text
front/
├─ README.md                   本書
├─ index.html                  HTML と Vue のマウント先
├─ package.json                依存関係・実行コマンド
├─ pnpm-lock.yaml              パッケージ解決情報
├─ tsconfig.json               TypeScript の型チェック設定
├─ vite.config.ts              Vue・開発ポート・API プロキシ設定
├─ playwright.config.js        E2E のブラウザー・サーバー設定
├─ src/
│  ├─ main.ts                  Vue とルーターの初期化
│  ├─ App.vue                  共通ヘッダー・メニュー・通知・RouterView
│  ├─ router/index.ts          URL と画面の対応・認証ガード
│  ├─ views/                   ルートごとの画面と遷移処理
│  ├─ components/              各画面の UI 部品
│  ├─ composables/useShop.ts    共有状態・API 取得・購入などの操作
│  ├─ types/api.ts             API のリクエスト・レスポンス型
│  ├─ api/http.ts              HTTP 通信・Cookie・CSRF・エラー処理
│  ├─ api/products.ts          商品一覧取得関数
│  ├─ utils/format.ts          JPY・数値・日本時間の日付表示
│  ├─ utils/categories.ts      カテゴリーの表示名変換
│  └─ styles.css               共通スタイル・レスポンシブ表示
├─ tests/
│  ├─ e2e/store.spec.js        ブラウザーテスト
│  └─ start-backend.mjs        テスト用 API・SMTP・メールボックス起動
└─ dist/                       ビルド時に生成する配布用ファイル
```

### フロントエンドの責務

`views/` はページ単位の接続を担当し、`components/` に型付き props とイベントを通してデータや操作を渡します。`useShop()` は単一の共有インスタンスを返すため、ページ遷移後もログイン状態、カート、取得済みの商品を共有できます。再読み込み時はバックエンドのセッションを確認して状態を取得し直します。

`types/api.ts` は `Product`、`Member`、`CartItem`、`Order`、`PointEntry`、`Review` と送信データの型を定義しています。たとえば `api<Product[]>('/products')` は商品配列のレスポンス型を指定します。TypeScript は開発・ビルド時の検査であり、受信した JSON の実行時検証を自動で行うものではありません。バックエンド DTO を変更した場合は型と利用箇所も更新してください。

### ページ一覧

| URL | 画面 | アクセス条件 |
| --- | --- | --- |
| `/` | 商品一覧・検索・並び替え・開催中のイベントスライド | 全員 |
| `/events/:id` | イベント詳細・画像・クーポン受取 | 閲覧は全員、受取はログイン必須 |
| `/products/:id` | 商品詳細・レビューのモーダル | 全員 |
| `/login` | ログイン | 全員 |
| `/register` | メール認証・新規会員登録 | 全員 |
| `/favorites` | お気に入り | ログイン必須 |
| `/cart` | カート・クーポン選択・注文フォーム | ログイン必須 |
| `/orders` | 注文履歴・配送状況・キャンセル | ログイン必須 |
| `/account` | 会員情報・ポイント履歴 | ログイン必須 |
| `/admin/products` | 商品・イベント・配送管理 | 管理者のみ |
| `/forbidden` | 権限不足の案内 | 全員 |
| その他の URL | ページが見つからない場合の案内 | 全員 |

未ログインで保護されたページを開くとログイン画面に移動し、成功後に元のページへ戻ります。一般会員が管理者 URL を開くと権限不足を表示します。バックエンドでも API の権限を検証します。ブラウザーの戻る・進む、直接 URL 入力、再読み込みに対応しています。

## 5. 実装済み機能

### 5.1 会員登録・認証

- メールアドレスを入力し、6桁の確認コードを送信・照合します。確認後に名前とパスワードを入力して登録できます。
- メールアドレスを変更すると、画面上の確認状態がリセットされます。送信・照合中の状態や、失敗時のメッセージを表示します。
- ログイン中の会員情報を共通メニューに表示し、画面からログアウトできます。

### 5.2 商品一覧・詳細・レビュー

- 日本語の商品一覧、カテゴリー絞り込み、商品名・説明の検索。
- 新着順、価格の安い順・高い順の並び替え。
- 価格、在庫、説明、画像 URL または絵文字の表示。
- URL から直接開ける商品詳細モーダル。
- レビュー一覧、平均評価、購入者による評価・レビュー投稿。
- 商品ごとに会員 1 人につきレビュー 1 件、本人のレビュー削除。

### 5.3 カート・お気に入り

- 会員ごとのカート追加、数量変更、削除、合計金額表示。
- 会員ごとのお気に入り追加・解除・一覧。
- 在庫切れや購入可能数量の確認。

### 5.4 注文・テスト決済

- 受取人、電話番号、住所の入力。
- カート内の商品をまとめて注文し、モックカード・モック簡易決済を選択。
- クーポン割引、ポイント利用額、支払額、テスト決済への同意の確認。
- 注文完了後のカート削除、本人の注文履歴と配送状況の表示。配送状況は「発送準備中 → 発送済み → 配達完了」の順に進みます。
- 発送前の注文全体のキャンセル、在庫復元、モック返金、ポイント精算。
- 過去の注文には購入時の商品名・単価を保持。

### 5.5 ポイント

- 通貨は整数の JPY、送料は無料、**1 ポイント＝1 円**。
- クーポンとポイント適用後の支払額の **1% を小数点以下切り捨てで獲得**。
- 利用上限は「保有ポイントの正の残高」と「クーポン割引後の商品合計」の小さい方。
- 全ポイント利用、利用後の支払額表示。
- マイページで残高と獲得・利用・返還・回収履歴を確認。

獲得ポイントを別の注文で使用してから元の注文をキャンセルすると、残高がマイナスになる場合があります。その場合は将来の獲得分で相殺し、正の残高になるまで利用できません。

### 5.6 管理者機能

- 管理者専用メニューと商品管理画面。
- 商品名、カテゴリー、整数の円価格、在庫、説明、絵文字、画像 URL の登録・編集。
- 商品一覧と編集対象の選択、保存後の表示更新。
- 削除の確認と販売終了処理。
- 「イベント」タブでタイトル、説明、掲載期間（JST）、割引額、公開設定を登録・編集。割引額を 0 円に設定するとバナーのみ掲載します。
- イベントの「削除」を確定すると管理一覧、公開バナー、詳細ページから消えます。発行済みクーポンと注文履歴は保持されます。
- 「配送」タブで注文の配送状況を更新。

### 5.7 共通 UI・データ管理

- 日本語の画面表示、JPY の金額表記、日本時間での日時表示。
- PC・スマートフォン向けのレスポンシブ表示。
- 処理中状態、成功通知、エラー表示、接続失敗時の再接続。
- スクロールバーの有無による共通メニューの横ずれを抑制。
- TypeScript による API データ、コンポーネント props・イベントの型指定。
- Vue Router のページ遷移、認証ガード、存在しないページ・商品の案内。

### 5.8 イベントバナー・クーポン

- 公開中のイベントを商品一覧上部のスライドに表示します。矢印、キーボード、スワイプで切り替えられます。バナーを選ぶとイベント詳細を開きます。
- イベント詳細は未ログインでも閲覧できます。クーポン受取にはログインが必要です。受取済みのクーポンはボタンが無効になります。
- 管理者はイベント編集画面で写真（JPEG・PNG・WebP、512 KB まで）を登録できます。
- クーポン受取とカート追加の結果は操作位置の近くに表示されます。カート追加時のポップアップからカートに移動できます。
- 会員はイベントごとに定額割引クーポンを1回受け取れます。カートで注文につき1枚を選択でき、クーポンを適用してからポイントを差し引きます。
- クーポンを使った注文を発送前にキャンセルすると、イベント終了前であればクーポンを再利用できます。

### 5.9 現在の対象外

実際の決済サービス接続、配送業者との連携、部分キャンセル、画像ファイルのアップロード、パスワード再設定、大量商品向けのページネーションは未実装です。商品画像は管理者が指定する HTTPS URL または絵文字を使います。

## 6. 動作確認の順序

1. バックエンドとフロントエンドを起動し、商品一覧を表示します。
2. 新規登録画面で受信可能なメールアドレスにコードを送信します。
3. コード確認後に名前・パスワードを入力して会員登録します。
4. お気に入りとカートに商品を追加し、再読み込み後も残っていることを確認します。
5. カートで配送先を入力し、モック決済への同意後に注文します。
6. 注文履歴とマイページで支払額・獲得ポイントを確認します。
7. 次の注文でポイントを使用し、注文キャンセル時の残高と履歴を確認します。
8. 管理者アカウントで商品登録・編集・販売終了を確認します。
9. 管理者の「イベント」タブで開催期間内のクーポン付きイベントを公開し、ログアウトした状態で商品一覧にバナーが表示されることを確認します。
10. ログインしてクーポンを受け取り、カートで選択して支払額を確認します。注文後に管理者の「配送」タブで発送済みに更新し、注文履歴への反映を確認します。

## 7. よくある問題

| 症状 | 確認する内容 |
| --- | --- |
| `pnpm.ps1` が実行できない | `pnpm.cmd` を使用します。インストール後はターミナルを開き直します |
| `5173` が使用中 | 既存の Vite を停止します。この設定では別ポートに自動移動しません |
| API に接続できない | バックエンド起動、`/api/health`、ポート、`API_PROXY_TARGET` を確認します |
| 認証メールが届かない | 迷惑メールを確認します。送信エラーが表示された場合はバックエンドのメール設定を確認します |
| 管理者メニューがない | 管理者アカウントでログインしているか確認します |
| 配布後、画面の再読み込みが 404 | Web サーバーで画面 URL の `index.html` フォールバックを設定します |
| E2E が起動しない | JAR の作成、JDK 21、ブラウザー、テスト用 4 ポートを確認します |
